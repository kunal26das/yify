# Crash audit — 29 September 2026

The audit started from `c1cee38`. Sentry returned 37 unresolved issues over 90 days,
including four regressions. Firebase's 90-day, all-event-type inventory displayed
86 issues but returned 85 distinct rows across its two pages: 31 crashes, 41 handled
exceptions and 13 ANRs. This discrepancy is retained rather than inventing a missing
issue. The private evidence is under `.expo/crashes-20260929/`; it is not committed.

## Android startup

The recent SoLoader issue `f919e6de34a52b36207b450bca6ebe7d` has 269 events affecting
53 users over seven days: 264 on 1.8.8 and five on 1.8.10. The process fails in
`MainApplication.onCreate`, before JavaScript and Sentry can initialize. Firebase
therefore sees crashes that Sentry cannot mirror.

One report identifies an x86-64 installed native-library directory but searches
ARM64 paths inside the APKs. SoLoader 0.12.1's direct-APK source chooses the first
reported supported ABI for these paths. The change enables Expo's
`android.useLegacyPackaging`, letting Android extract the matching native libraries
at installation and letting SoLoader use the installed directory.

A JVM probe against the actual resolved SoLoader AAR reproduces the wrong-ABI
lookup failure. Changing the fixture to the correct ABI finds the same APK library.
Enabling extraction disables direct loading and resolves both `libc++_shared.so`
and `libreactnative.so` from the installed directory. Android state and extraction
are simulated in that probe; it records the native-load call without executing
`dlopen`. It does not reproduce every historical device crash.

`scripts/check-android-native-libs.mjs` checks actual APKs, including a base APK plus
ABI splits generated from an AAB. It requires extraction in the compiled manifest,
compressed native-library entries, the requested ABIs, the core libraries, valid
ZIP payloads and matching ELF architectures. It rejects the old direct-loading
configuration. The Android setting affects both standalone APKs and bundle-derived
APKs through the Gradle DSL; final bundle-derived APK validation is required.

This native change uses runtime **1.8.12 / version code 94** and cannot be delivered
to older runtimes over the air. Extraction also consumes additional installed disk
space. It does not remove support for any of the four existing ABIs.

## Preview regressions

YIFY-22 and YIFY-23 are exclusively preview events, with five and eleven events
respectively. The September 29 regression matches an ad hoc SDK-upgrade QA runner
at localhost:58841 that served static files without the catalog API.

`scripts/check-web-preview.mjs` checks prerendered HTML routes and both catalog JSON
response envelopes before a browser test starts. The actual QA runner now rejects its former
static-only invocation before launching Chrome. With its explicit same-origin
catalog proxy, home, movies and shows rendered with 39 successful catalog requests,
no local 404s and no JavaScript page exceptions. Outbound telemetry was blocked
before navigation; the Sentry counts and last-seen timestamps did not change.

For a Hosting export, use Expo's server preview. A static Pages preview must supply
its intended same-origin catalog fixtures or proxy. A plain static server cannot
execute Expo API routes. Run the preflight against the preview base URL before QA:

```sh
node scripts/check-web-preview.mjs http://127.0.0.1:8793/
```

## Existing fixes and deliberate verification events

- Firebase `e07fd520f8aa40c7024358f17c0b3367` matches YIFY-24 exactly: UMP 4.0.0's
  `zzcr.zzl()` reads an empty HTTP error body with `Scanner.next()`. The checksum-
  guarded fix in `43bf8d7` shipped in Android 1.8.9 (91), with 26 actual-SDK cases,
  five incompatible-bytecode rejection checks and release/emulator verification.
  This Firebase event is on 1.8.8, which lacks that native fix.
- Firebase `004aed0767dd9235f6e18d3b14943568` is an asynchronous StoreReview callback
  using a missing Activity, last reported on 1.7.9. Commit `9cecc57` removed the
  startup review request. The current app never imports or calls that SDK; its
  explicit Preferences rating action opens the store. Tests exercise delayed
  update checks and failures without starting a review. The unused dependency's
  callback still contains the upstream defect; it was not patched speculatively.
- Firebase `77ff1260158bc72b21e24873621a5563` is the missing ExpoBlur native-view
  error. Commit `7c2ef07` introduced the solid-surface error boundary. Its latest
  September 27 event came from 1.1.4 and its stack lacks that boundary; the affected
  version range ends at 1.4.2. The current fallback passed three actual React render regressions, including the
  exact native error and retention of an interactive child.
- Clearly named crash-bridge verification groups are deliberate probes, not
  customer crashes. Their closure is recorded separately from application fixes.
  Device model or unusual hardware data alone is not proof of a synthetic event.
